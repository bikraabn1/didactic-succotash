EPIC 1: REGISTRATION FEATURE (BACKEND API FIRST)
==============================================================================

Card 1.1: [Backend] Submit Registration API
Status: To Do
Epic: Registration
Type: Feature
Target: Student

Description:
Endpoint for students to submit new registration data.

Checklist:
- [ ] Validate request payload (full_name, nisn, school_origin, phone, address, average_score).
- [ ] Validate NISN format and ensure uniqueness.
- [ ] Business Rule: 1 user can only have 1 registration record (unique constraint check).
- [ ] Auto-generate a unique registration_number (e.g., REG-2026-XXXX or nanoid).
- [ ] Set default registration status to 'pending'.
- [ ] Save to database linked with authenticated user's ID (`user_id`).
- [ ] Return standard JSON response: status, message, and registration data.

Acceptance Criteria:
- Authenticated student successfully submits registration form.
- Attempting to submit a second time returns 400/422 (Already Registered error).

Card 1.2: [Backend] Registration Authorization & Policy
Status: To Do
Epic: Registration
Type: Security / Policy
Target: Student, Admin

Description:
Implement authorization rules using AdonisJS Bouncer to protect registration resources.

Checklist:
- [ ] Complete `show` method in `RegistrationPolicy`:
      - Students can only view if `user.id === registration.user_id`.
- [ ] Create `update` method in `RegistrationPolicy`:
      - Students can only update their own record.
      - Students can only update if status is still `pending` (lock form if `approved` or `rejected`).
- [ ] Ensure `before()` hook in policy bypasses checks for `admin` role.
- [ ] Apply Bouncer authorization checks in `RegistrationsController` for show & update actions.
- [ ] Ensure 403 Forbidden exceptions return a clean, descriptive JSON response.

Acceptance Criteria:
- Students cannot view or modify registrations belonging to other students (403 Forbidden).
- Admins can view and update all registrations without restrictions.


------------------------------------------------------------------------------

Card 1.3: [Backend] Get My Registration & Detail API
Status: To Do
Epic: Registration
Type: Feature
Target: Student, Admin

Description:
Endpoints to retrieve the authenticated user's registration data or fetch by ID.

Checklist:
- [ ] Create endpoint `GET /api/v1/registrations/me`:
      - Query registration by `auth.user.id`.
      - Return 404 if the user has not registered yet.
- [ ] Complete endpoint `GET /api/v1/registrations/:id`:
      - Authorize access using Bouncer `show` action.
      - Support eager loading of relationships when needed (documents, score).
- [ ] Handle 404 Not Found error gracefully.

Acceptance Criteria:
- Logged-in students can fetch their own application via `/registrations/me`.
- Access to `/registrations/:id` is strictly governed by Bouncer policy.

Status: Backlog
Epic: Scoring
Type: Feature
Target: Admin

Description:

Checklist:
